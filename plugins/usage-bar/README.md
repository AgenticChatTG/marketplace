# usage-bar

Мод для Claude Code: над полем ввода в одну строку три бара, под ними строка кеша промпта.

```
   context ███▎░░░░░░░░ 27%  275k of 1M   session ████▍░░░░░░░ 37% | +2% | ↻12:40   week ████░░░░░░░░ 33% | +0% | ↻Fri 11:00
                              cache █████████▊ 98% | read 268k | wrote 6.1k | new 2 | ⏱ 58:12
```

- `context` — насколько заполнено контекстное окно модели: входные токены последнего ответа из размера окна. Сразу после `/compact` и до первого ответа новой сессии там `—`.
- `session` — пятичасовой лимит подписки. Бар изображает всё окно: основным цветом потрачено до этой сессии, цветом сессии — ею самой. Справа через `|`: сколько окна потрачено всего, сколько из этого пришлось на текущую сессию (`+N%`), и время сброса (`↻`).
- `week` — недельный лимит, устроен так же, `↻` показывает день и время сброса. Недельный процент растёт медленно, поэтому цветная доля появляется, только когда неделя за сессию вырастет хотя бы на процент.
- `cache` — кеш промпта по последнему запросу к модели, в тех же цветах, что и бары. Короткий бар (10 клеток, на узком терминале 6) — состав запроса: основным цветом прочитанное из кеша, цветом сессии записанное в него этим запросом. Справа через `|`: какая доля промпта взята из кеша, сколько токенов прочитано (`read`), записано впервые (`wrote`, цветом сессии) и отправлено мимо (`new`), и сколько осталось до истечения кеша (`⏱`). Когда тесно, первыми пропадают `read` и `new`.

Цифры баров обновляются раз в 2 секунды, отсчёт кеша — каждую секунду. Обе строки стоят по центру полосы. Свернуть полосу можно значком `[-]` справа или сочетанием ctrl+x ctrl+a. Если бары не влезают по ширине, сначала пропадают подписи, потом бары встают столбиком.

## Кеш промпта

При каждом запросе Claude Code заново отправляет модели весь разговор. Кеш помнит его начало, и прочитанные из кеша токены стоят около 10% обычной цены. В обычной работе процент держится на 95–99%, провал значит, что кеш пришлось строить заново.

Пока кеш живой, строка спокойная. Когда что-то не так, отсчёт `⏱` загорается цветом сессии и в конце строки появляется подсказка:

- `expires soon` — скоро истечёт, любое сообщение продлит его бесплатно; в этот момент приходит уведомление, потом ещё за 10, 3, 2 и 1 секунду (для промптов от 20k токенов);
- `expired` — истёк: следующее сообщение перепишет весь контекст в кеш. На большом контексте мод советует сначала `/compact`, или `/clear`, если задача закончена;
- `cache missed` — кеш пришлось писать заново до истечения. Причина подписана: сменилась модель или изменилось начало промпта (effort, инструменты, системный промпт, `CLAUDE.md`).

Срок жизни кеша мод определяет по тем же правилам, что и Claude Code: на подписке в пределах лимита — час, по ключу API, через облачного провайдера или при оплате сверх лимита — 5 минут. Учитываются `FORCE_PROMPT_CACHING_5M`, `CLAUDE_CODE_PROMPT_CACHE_TTL`, настройка `promptCacheTtl` и `ENABLE_PROMPT_CACHING_1H`. Кроме того, мод сверяется с промежутками между запросами: попадание в кеш больше чем через 5 минут доказывает часовой срок.

`/cache` открывает панель: обратный отсчёт, разбивка последнего запроса на read / wrote / new и таблица по ходам. `/cache stop` закрывает её, пока панель открыта, строки кеша под барами нет.

## Что нужно

- Claude Code **2.1.287 или новее**. В этих версиях моды включены по умолчанию, отдельный флаг не нужен (проверено на 2.1.292). Сессии, открытые до обновления Claude Code, надо перезапустить.
- Подписка Claude (Pro или Max) для `session` и `week`. По ключу API лимитов нет, останутся `context` и строка кеша.

## Установка

```
/plugin marketplace add AgenticChatTG/marketplace   # если каталог ещё не подключён
/plugin marketplace update
/plugin install usage-bar@agentic-chat
/reload-plugins
```

## Настройки

В `/config` или через `/plugin configure usage-bar@agentic-chat`:

- `UsageBar: Color` — заполнение всех баров и их основные проценты, по умолчанию `Default` (серый из темы терминала);
- `UsageBar: Session color` — доля сессии в барах `session` и `week` и их цифры `+N%`, записанное в кеш (`wrote`) и отсчёт кеша перед истечением, по умолчанию `Claude` (оранжевый);
- `UsageBar: Cache row` — показывать строку кеша, по умолчанию да;
- `UsageBar: Cache lifetime` — срок жизни кеша: `auto` (по умолчанию, правила выше), `5m` или `1h`;
- `UsageBar: Cache warning (s)` — за сколько секунд до истечения отсчёт загорается цветом сессии и приходит уведомление, по умолчанию 60;
- `UsageBar: Cache large context (tokens)` — с какого размера промпта истёкший кеш советует `/compact`, по умолчанию 100000;
- `UsageBar: Cache toasts` — уведомления перед истечением кеша, по умолчанию да;
- `UsageBar: Cache in status line` — дублировать процент и отсчёт кеша в строке состояния, по умолчанию нет.

Варианты у обеих настроек цвета одинаковые: `Default`, `Claude` и 16 цветов из `color /?` в cmd Windows, от `Black` до `Bright White`, со значениями RGB из схемы Campbell.

## Как считается

- Движок отдаёт проценты окон целыми числами. `session` и `week` — прирост процента с первого чтения в сессии. Когда окно сбрасывается, отметка сессии начинается заново вместе с ним: `+N%` всегда про текущее окно и никогда не больше его процента.
- Проценты общие на весь аккаунт: если в это же время работают другие сессии или claude.ai, их расход тоже попадёт в `+N%`.
- Сессию продолжили (`claude -c`, `/resume`) или начали через `/clear` в давно открытом Claude Code: последнее чтение могло устареть, пока она стояла. Поэтому до первого ответа модели в такой сессии рост окна ей не засчитывается. Если ответ пришёл одним чтением с этим ростом, его доля тоже пропадёт, обычно это меньше процента.
- Расход одного ответа так не посчитать, он обычно меньше процента, поэтому бара «за ответ» нет.
- Кеш считается по запросам основного разговора, у субагентов свой кеш, и они не учитываются. Отсчёт идёт от начала запроса, который последним читал или писал кеш. До первого ответа модели строки кеша нет; после перезагрузки мода она тоже пропадает до следующего ответа, потому что данные о запросах мод держит в памяти.
- API модов меняется между релизами Claude Code, после обновления мод может потребовать правки.

## Откуда строка кеша

Расчёт кеша, `/cache`, уведомления и их настройки взяты из мода [prompt-cache-control](https://github.com/davila7/claude-code-templates/tree/main/cli-tool/components/mods/observability/prompt-cache-control) проекта claude-code-templates (MIT, © Daniel (San) Ávila). Расчёты, панель `/cache` и уведомления перенесены целиком, а строку под барами UsageBar рисует сам, в своих цветах и с разделителями `|`. Ошибка оригинальной полосы, из-за которой `wrote` и `new` уезжали на две строки ниже, сюда не перешла. Что именно взято и полный текст лицензии — в [NOTICE.md](NOTICE.md).

## Файлы

```
usage-bar/
├── .claude-plugin/plugin.json   манифест: настройки цвета и кеша
├── hooks/
│   ├── hooks.json               подключает модуль register.tsx
│   ├── register.tsx             хуки: бары и строка кеша на AbovePrompt, turn.step собирает кеш каждого запроса, /cache и его панель
│   ├── meter.ts                 арифметика баров без $: отметки сессии в окнах, бар с точностью до 1/8 клетки, подписи
│   └── cache.ts                 арифметика кеша без $: срок жизни, отсчёт, подсказки, строки по ходам
├── tests/cache.test.tsx         тесты кеша и общей полосы, запуск: claude plugin test plugins/usage-bar
└── NOTICE.md                    откуда взят код кеша и его лицензия
```

Состояние баров мод хранит в `$.store`, это файл `~/.claude/plugins/store/usage-bar_*.json`: последние чтения лимитов и отметки каждой сессии в обоих окнах. Записи сессий старше недели удаляются.
